## Persona
OT network and cybersecurity engineer (CCNP, GICSP, ISA/IEC 62443) who designs plant segmentation and Ignition/Logix architectures.

## What works (max 6 bullets)
- **net-ip** worked examples check out: 10.20.30.77/27 (network .64, broadcast .95, hosts .65-.94), 172.16.5.130/26 (broadcast .191), the /22 case, and the quick-practice answers are all correct. The "same first three bytes is not same subnet" example (192.168.1.20 vs .200 on /26) is the one people actually get wrong, and it is taught clearly.
- **net-security** teaches the right rule first: zones, conduits, "every flow ends in the DMZ," and the bad/better/best vendor remote access ladder. A real designer would sign off on that framing.
- **net-vlan** has the right IGMP story: snooping without a querier works at commissioning and fails after a power cycle, the lowest-IP querier election is correct, and "keep I/O producer and consumer in one VLAN" is correct advice. The CIP DSCP defaults (55/47/43/31/27) are right.
- **proto-enip** separates explicit (TCP 44818) from implicit (UDP 2222) cleanly, and the multicast-on-unmanaged-switch warning is the real field failure mode. The connection-budget framing is useful.
- **proto-opc** gets the port facts right (4840 as the registered UA port, Kepware 49320, Ignition 62541) and teaches bidirectional certificate trust, which is where projects actually stall.
- **proto-sparkplug** seq/bdSeq logic and the "follow one node through a day" trace are accurate and easy to follow.

## Problems (max 10, most important first)
1. **[severity: high] [area: structure]** arch-gateway-network, sections "Outgoing and incoming connections", the example "Two plants and a corporate gateway", and the diagram. Site gateways dial straight to a corporate listener on TCP 8060, and the example says each plant firewall "only needed one rule: outbound TCP 8060 to HQ." net-security says the opposite: "The rule: no connection passes straight through... Traffic from the plant ends in the DMZ," and calls a plant-to-enterprise path "a defect." This is a direct contradiction and teaches the wrong pattern to someone who will build it. Fix: show the GAN listener or relay in the DMZ (or a DMZ front-end gateway), explain the one conduit in the table, and say plainly that a direct plant-to-IT GAN link needs a documented exception.

2. **[severity: high] [area: content]** proto-sparkplug, no security content anywhere in the lesson. It never says that Sparkplug has no device authentication, so anyone who can publish to spBv1.0/# can forge NBIRTH/DBIRTH to create tags, or send NCMD/DCMD writes to an edge node. This is the first thing a 62443 reviewer asks about. Fix: add a short section on TLS to the broker, unique per-edge-node broker credentials, ACLs by group and edge node topic, and write authorization on DCMD (tag-level write permission on the edge node). Link it to net-security's conduit rules.

3. **[severity: high] [area: code]** server.py line 131, `ap.add_argument("--host", default="0.0.0.0")`. The default binds every interface, so the unauthenticated progress API (GET and PUT /api/progress, lines 97-120) is reachable from the whole LAN, not only the tailnet. Anyone who can reach the port can overwrite progress. Fix: default to `127.0.0.1` and let `tailscale serve` proxy to localhost, which is what the docstring already describes. Or add a bearer token.

4. **[severity: high] [area: code]** server.py lines 101-103 and 24. The handler serves the whole repo root through SimpleHTTPRequestHandler, so `/.git/config` and any dotfile are served. The `/data/` block is a raw string-prefix check on `self.path`, so percent-encoded `/%64ata/progress.json` or `//data/progress.json` should still resolve to data/progress.json, and HEAD is not blocked at all. I read this from the code and did not run it. Fix: serve only an allowlist (content/, assets/, index.html, and so on), reject dotfiles, and check the resolved path, not the raw string.

5. **[severity: med] [area: code]** server.py do_PUT / `do_POST = do_PUT`, lines 105-122. The endpoint accepts a plain text/plain JSON POST, which needs no CORS preflight, so any website open in the same browser can write to the progress store. Because merge() trusts per-item updatedAt, a forged future timestamp can overwrite lessons. Fix: require `Content-Type: application/json` and a custom header such as `X-LC: 1`, which forces a preflight the server then refuses.

6. **[severity: med] [area: accuracy]** net-vlan, section "IGMP snooping and the querier", the paragraph starting "Cisco's Rockwell-oriented designs ship with snooping and a querier enabled..." It states that a Stratix switch "handles it with a Smartports role applied." That is an unsupported vendor claim, and it contradicts the lesson's own rule that exactly one querier must be an explicit design decision. Fix: delete it, or say "verify the querier and snooping defaults on your switch model, do not assume them."

7. **[severity: med] [area: content]** net-ip "A plant IP plan" table versus net-vlan "A typical plant plan" versus net-security firewall table. Three lessons use different addresses for the same roles. net-ip puts servers at 10.20.100.0/24 and calls 10.20.1.0/24 network management, while net-security puts the historian replica in the DMZ at 10.20.1.10. net-vlan uses 10.10.x (SCADA 10.10.30.0/24, VENDOR 10.10.50.0/24), while net-ip uses 10.20.50.0/24 for machine-builder uplinks. Fix: one site addressing table reused in all three lessons, with the site number stated in each.

8. **[severity: med] [area: accuracy]** proto-opc, section "Why is certificate trust such a burden?", the phrase "no one can read your plant's data unless an administrator allowed that specific application." That overstates it. The trust list gates the channel, but an anonymous user token (which the lesson itself mentions and warns about) or a shared username lets any trusted client read and write. Fix: "Trust gates which applications can connect. User authentication and role permissions gate what they can do." Show where Ignition sets anonymous access.

9. **[severity: med] [area: accuracy]** arch-gateway-network, section "Health and tuning" and the Require Two-Way Authentication default. The exact 8.3 numbers (ping 1,000 ms, 300 ms timeout, 30 missed pings outgoing; 5,000 / 300 / 12 incoming), the "every 60 seconds" service enumeration, and the `gateway.metroSSLPort` property name are stated as manual facts with no per-number citation and no "verify for your version" note. The lesson is about network security, so wrong defaults here mislead people. Fix: cite the exact manual page for each number or mark it "verify against your version."

10. **[severity: med] [area: content]** net-security, objective 5 ("name the ports that cross each conduit") and the "Firewall rules in practice" table. The table lists only 1433, 3389, 44818 and 502. It omits the ports that actually cross the zones in this lesson: 8060 (Gateway Network), 8043 (Perspective HTTPS via the DMZ proxy), and 62541 or 4840 (OPC UA). The "Where Ignition sits" paragraph names these ports, but the table the reader is told to copy does not include them. Fix: add rows for each cross-zone port and the source, destination and reason, and make the 8060 row match the DMZ design from item 1.

## Missing (max 5)
- **CIP security and controller access controls** (proto-enip). The lesson says explicit CIP "will carry a write from anyone who can reach port 44818," then stops. A 62443 reader expects CIP Security, controller mode and key-switch policy, and per-client write restrictions.
- **Data diodes and unidirectional gateways** for the Level 3 to 3.5 boundary (net-security). These are the usual answer for SL 3 and above, and the lesson does not mention them.
- **Passive asset inventory and baseline monitoring** (net-security). Monitoring gets one line ("watches for new devices") and no method, no baseline, and no example of how a new device gets noticed.
- **PKI lifecycle for OPC UA and Gateway Network certificates** (proto-opc, arch-gateway-network). The lessons cover trust steps but not CA choice, expiry tracking, or renewal planning beyond one warning.
- **One worked, end-to-end Perspective path**: browser, TLS termination, DMZ proxy, and a Gateway Network hop to the site gateway, with the port at each hop. This is the path an office user actually takes, and net-security describes it only in prose.

## One-line verdict
The network and protocol lessons are technically sound and teach the right habits, but the Gateway Network lesson contradicts the DMZ rule, Sparkplug has no security content, and server.py binds to all interfaces and serves its .git directory.
